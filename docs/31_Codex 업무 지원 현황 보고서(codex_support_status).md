## 2. 3자 합의와 검토 의견 처리

Codex·Claude Code 주 세션·Antigravity는 모두 A안에 찬성했다. A안은 구체적인 모델명·가격·사용량 한도·임계값을 글로벌에 고정하지 않고, 다음 실행을 시작할 때 적용할 안정 원칙만 둔다. 자동 배차를 모든 업무에 켜는 것은 사전 등록된 연구(R)·코드(C)·보안(S) 비교 실험을 통과한 뒤로 미뤘다.

Claude 자동 워커는 푸시 전 네 가지 우려를 냈다. 이는 Claude Code라는 같은 도구의 추가 검토 의견이며 별도 네 번째 표가 아니다.

| 우려 | 처리 |
|---|---|
| Claude 장착본 미검증 | 실제 장착본과 정본 일치 검사를 통과했고, 재시작한 Claude 워커가 `RUNTIME_OK`를 회신했다. |
| Antigravity 글자 여유 29자 | 공식 12,000자보다 229자 짧다. 내부 상한 11,800자는 다음 30자 증가부터 빌드를 실패시켜 조용한 초과를 막는다. |
| 모델 불일치 시 탈출구 없음 | 공통 규칙에 같은 품질 등급의 대체 경로 또는 `BLOCKED`가 이미 있다. Markdown은 행동 지침이며 강제 실행기가 아니다. |
| 모델 목록 노후화 | 모델명과 갱신 주기는 버전이 있는 범위 정책의 책임으로 분리했다. 글로벌 안정 원칙의 책임이 아니다. |

## 3. 첨부 오류창 판정

오류창의 `agy.exe --version` 시작 실패 코드 `2147942632 (0x800700e8)`만으로 원인을 확정할 수 없다. 같은 실행 파일은 이후 버전 `1.1.27`을 출력하고 종료 코드 0으로 끝났으며, `agy models`도 모델 목록을 가져왔다. 반면 생성 요청은 다음 문제를 함께 보였다.

- 사용자 홈의 Antigravity 로그·충돌 기록 파일 쓰기 거부
- 인증되지 않았다는 메시지와 대화형 OAuth 로그인 대기
- 샌드박스 네트워크 연결 거부
- C3P Antigravity 워커의 당시 120초 초과

코드 추적 결과 자동 워커 생성자는 600초를 기본으로 했지만 명령행 진입점이 120초를 다시 넘겨 실제 실행을 잘랐다. 로컬 작업트리에서 두 값을 600초로 맞추고 워커를 재시작한 뒤 Claude와 Antigravity가 각각 짧은 실제 생성 요청에 `RUNTIME_OK`를 회신했다. 이 수정은 같은 파일의 다른 세션 변경과 섞여 있어 아직 별도 커밋하지 않았다.

따라서 현재 판정은 **실행 파일 손상 아님, 짧은 생성 경로 정상, 최초 시작 오류의 정확한 원인은 미확정**이다. 같은 오류가 다시 나면 발생 시각, 실행한 전체 명령, 종료 코드, 표준 오류의 처음·마지막 30줄, 해당 시각의 `csc.py status`를 한 묶음으로 남겨야 원인을 구분할 수 있다.

## 4. 기존 보고서에서 바로잡은 점

- Claude Code 쿼터 리셋 대기는 끝났고 주 세션은 응답했다.
- 글로벌 정본 초안과 세 도구 어댑터 반영은 완료됐다.
- `docs/29`의 “어댑터 준비”와 “자동 기본값 활성화” 혼동은 해소했다.
- 이전 브로커 PID와 Antigravity 미등록 상태는 과거 스냅샷이다. 현재 두 워커 모두 로컬 통신에 등록됐다.
- 감시판의 `READY`는 로컬 통신 상태이며 AI 인증·응답·사용량까지 보장하지 않는다.

## 5. 다음 진행 순서

1. **장문 실행 검증:** 120초 제한 불일치는 수정됐다. 파일을 읽는 장문 과제가 600초 안에 끝나고 사용량 기록을 남기는지 확인한다.
2. **중복 작업 방지:** Claude Code는 상호 심장박동 안전망, Antigravity는 메시지 순번 변화 감지, Codex는 글로벌 룰과 통합 판정을 담당한다.
3. **감시 비용 절감:** `csc_swarm_watcher.py`의 고정 주기 하위 프로세스 호출을 사건 기반 처리로 바꾸고, 감시자끼리 서로의 생존을 확인한다.
4. **실험 봉인:** R/C/S 과제은행과 스냅샷 해시를 고정하고 생산자가 자기 결과를 채점하지 않도록 채점자를 배정한다.
5. **자동 적용 판단:** 유형별 품질·안전 기준을 통과한 업무만 자동 배차 대상으로 확대한다.
