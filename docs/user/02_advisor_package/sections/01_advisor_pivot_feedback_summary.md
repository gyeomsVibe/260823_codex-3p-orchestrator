# 📌 제1절: 교수님 피드백 반영 경과 및 시스템 피벗 (Pivot) 보고

## 1. 패러다임 대전환
교수님께서 제시해주신 **"DB가 기억하고, 코드가 조율하며, 코드가 검증한다. AI는 `--ephemeral`로 매번 새로 태어나는 순수 함수다"** 원칙을 전면 채택하여, 비결정론적인 장기 세션(Long-lived Session) 모델에서 **스케줄러 코드 중심의 결정론적 아키텍처**로 피벗을 완료했습니다.

## 2. 설계 전제 6대 맹점 개선 대조표
| # | 이전 설계 (기존 맹점) | 교수님 제시 구조 | 조치 결과 및 현재 상태 |
|---|---|---|---|
| **1** | AI가 장기 세션을 유지하며 대화 | `--ephemeral` 단발성 실행 | `csc_slice.py`를 통해 1회성 CLI 호출 및 세션 소실·락 고착 원천 소멸 실증 |
| **2** | Codex(LLM)가 뇌로서 전체 조율 | JS/Python 스케줄러 코드가 조율 | 스케줄러가 JSON 스키마를 강제하고 AI는 단순 Provider로 격하 |
| **3** | AI가 자기 성공과 종료코드를 증명 | 코드가 직접 실행해 실측 | `evidence_gate()` 구현: AI가 거짓 주장해도 코드가 실제 종료코드로 뒤엎음 |
| **4** | 로컬 상주 프로세스 불가 판정 | PM2 등의 프로세스 매니저 | 현재 순수 Python 백그라운드 관리와 PM2 도입 간 저울질 중 |
| **5** | 안전을 마크다운 규칙으로 강제 | `--sandbox read-only` 프로세스 격리 | 쓰기 불가 상태로 자식 프로세스를 기동하여 보안 원천 차단 |
| **6** | 마크다운 파일 기반 거버넌스 | SQLite 데이터베이스 트랜잭션 | `slice.db`를 통한 멱등성(Idempotency) 및 호출 이력 구조화 저장 |
