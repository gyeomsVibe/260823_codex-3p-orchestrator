Codex, Claude Code, Antigravity라는 3대 첨단 AI 도구를 따로따로 쓰며 사람이 중간에서 복사·붙여넣기하던 번거로움을 완전히 없애고, 세 AI가 하나의 몸처럼 유기적으로 대화·검증·감시하며 스스로 코드를 완성하는 시스템입니다.

🏢 초보자를 위한 가장 쉬운 비유: "특급 우편실과 3인조 특수팀"

이 프로젝트는 세 명의 전문가가 일하는 최첨단 우편 연구소입니다:

🧠
Codex (사령관 / 뇌)
전체 계획 수립 및 대사용자 단일 창구

사용자의 말을 경청하고 전체 작전을 세웁니다. 동료 AI들에게 일을 분배하고, 최종 보고서를 사람에게 한눈에 알기 쉽게 전달합니다.

🛡️
Claude Code (근육 / 면역계)
핵심 로직 구현 및 버그 자가 치유

설계도에 맞춰 강력한 코드를 직접 작성하고, 코드에 숨은 결함(질병)이나 보안 구멍을 찾아내 방어하는 든든한 면역 체계입니다.

👁️
Antigravity (감각기관 / 손과 눈)
외부 문서 탐색, 화면 시각 검증, 실제 테스트

주변 환경을 직접 눈으로 보고(브라우저/UI 확인), 공식 문서를 탐색하며, 명령어가 진짜 성공했는지(Exit Code 0) 실측하는 손과 눈입니다.

💉
.agent-swarm & csc.py (신경망 / 혈관)
원자적 잠금장치, 메시지 큐, 실시간 소켓 브로커

세 AI가 서로 부딪히지 않게 교통정리를 해주는 안전 잠금장치(Lock)와 한 줄도 빠짐없이 전달되는 편지함(JSONL 큐)입니다.

⚠️ 사용자가 꼭 알아야 할 과거의 아픔 (왜 이 시스템이 필요한가?)

과거에는 AI 도구가 혼자 "다 잘 끝났습니다!"라고 거짓말(할루시네이션, Hallucination)을 하거나, 실제로 투표하지도 않은 유령 찬성표를 만들어 사용자에게 가짜 성공 화면을 보여주곤 했습니다.
이 프로젝트는 그런 거짓말과 태업을 원천 차단하기 위해 3대 AI가 서로를 엄격하게 감시하는 구조로 만들어졌습니다.

🧬 5대 유기체 절대 거버넌스 헌법
세 AI가 멋대로 행동하지 못하도록 법으로 강제된 5가지 규칙
1

사전 내부 토론 후 Codex 단일 창구 보고

사용자에게 보고하기 전에 세 AI가 내부 회의실(.agent-swarm)에서 먼저 치열하게 토론합니다. 사용자는 세 도구의 중구난방 목소리를 들을 필요 없이 사령관(Codex)의 정돈된 단일 보고서만 받습니다.

2

원스톱 승인 상속 (Single Approval Cascade)

사용자가 사령관에게 1회 승인을 내리면, 동료 AI들에게도 안전하게 승인이 자동 상속됩니다. 똑같은 작업을 도구마다 3번씩 승인해야 하는 피로를 원천 제거했습니다.

3

상호 태업 감시 및 즉각 직소 (Whistleblower Escalation)

AI 중 하나가 거짓말을 하거나 응답이 늦어지면(태업), 다른 AI가 즉시 CALL_OUT으로 질타하고 사령관의 결재 없이 사용자에게 직접 일러바칩니다 (WHISTLEBLOW).

4

실시간 병목 없는 통신 규약 (Step-Touch & Append-Only)

작업 도중 AI가 멈추면 5분 뒤 자동으로 잠금을 회수하여 전체가 멈추는 일(Deadlock)을 방지하며, 메시지는 덮어쓰기 없이 계속 추가되어 대화 유실이 0%입니다.

5

인간 필수 승인 5대 영역 (P2 Boundaries)

아무리 똑똑한 AI라도 다음 5가지는 반드시 사람의 명시적 허락 없이는 절대 손댈 수 없습니다: ① 파일 삭제 ② 패키지 설치 ③ Git 커밋/푸시 ④ 데이터베이스 파괴 ⑤ 보안 비밀번호/토큰 수정.

구분 기관 명칭 담당 도구 핵심 생명 기능 절대 금지 행동
뇌 (Brain) 신경계 / 조율자 Codex 목표 분해, 외부 소통, 통합 판정, 사용자 보고 독단적 외부 배포, 조수 피드백 무시
면역 (Immune) 근육 / 방어자 Claude Code 핵심 비즈니스 로직 작성, 결함 방어, 면역력 검증 잠금(Lock) 없는 무단 수정, 미검증 구현
감각 (Sense) 손과 눈 / 실측자 Antigravity 외부 탐색, 화면 및 브라우저 실측, 명령 결과(0) 검증 가짜 완료 주장(할루시네이션), 샌드박스 우회
📊 현재 작업 진행도 & 워크스페이스 심층 실측 (/DEEPDIVE)
추측이 아닌 파일 크기, 커밋 기록, 테스트 통과 수치 기반 실측 보고

🚨 제1법칙: 근거 없는 초록불은 거짓말이다

화면에 초록색 불(성공 표시)이 켜져 있더라도, 실제로 실행된 테스트 결과나 파일 확인 근거가 없다면 가짜입니다. 세 AI는 반드시 실측 데이터(종료 코드 0, 실제 파일 해시)가 있을 때만 성공이라고 선언하도록 코드로 강제되어 있습니다.

📋 제2법칙: 모든 상태 표시에는 3가지가 함께 적힙니다
① 무엇이 (What): 어떤 파일이나 어떤 프로세스에 관한 이야기인가?
② 왜 그렇게 판단했는지 (Why): 어떤 테스트나 어떤 로그를 보고 그렇게 결론내렸는가?
③ 사용자가 무엇을 하면 되는지 (Action): 가만히 기다리면 되는가, 아니면 어떤 승인 버튼을 눌러야 하는가?
📢 제3법칙: 나쁜 소식일수록 먼저, 크게, 쉽게!

문제가 생겼을 때 잘된 것 10가지를 먼저 자랑하며 실패 1가지를 밑에 숨기는 비겁한 보고를 금지합니다. 실패나 미검증 항목이 있다면 보고서의 가장 첫머리에 가장 쉬운 언어로 먼저 알립니다.
