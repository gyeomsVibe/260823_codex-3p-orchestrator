## 1. 기획 (Frame) — 왜 이 기능이 필요한가요?

### 1.1 해결하려는 진짜 문제
- **상황**: AI 3대 도구(Codex, Claude Code, Antigravity)가 협업할 때, 사용자가 자리를 비우면 AI들끼리 자유롭게 대화를 주고받다가 **고가의 외부 클라우드 토큰(token, 인공지능에 글자를 보낼 때 소모되는 요금 단위)**을 탕진할 위험이 있습니다.
- **목표**: 
  1. 사용자가 없는 동안에는 **외부 토큰 비용을 0원으로 억제**합니다.
  2. 시스템에 진짜 새로운 사건(코드 수정, 테스트 요청 등)이 발생했을 때만 **최대 5턴·15분 이내로 엄격히 제한된 토론회**를 열어 안전한 결과 카드만 준비합니다.
  3. 파일 삭제나 깃 푸시 같은 위험 행동은 **사용자 승인 없이 절대 실행하지 않고 멈춥니다**.

## 2. 검토 (Review) — 4대 렌즈 및 레드팀 비판 분석

| 평가 렌즈 (Lens) | 분석 내용 (Analysis) | 최종 판정 |
|---|---|---|
| **가치성 (Value)** | 사용자가 안심하고 외출할 수 있으며, 복귀 후 한눈에 깔끔한 3단 결과 카드만 확인 가능 | **최우수 (Go)** |
| **실현가능성 (Feasibility)** | 외부 통신 없이 로컬 파이썬 소켓 데몬과 순수 상태 머신으로 구현되어 지연 시간 0ms | **완전 구현 (Go)** |
| **지속가능성 (Viability)** | 대기 중 외부 AI 호출 0회, 로컬 0원 감시로 예산 소모 제로(Zero-Token) 달성 | **지속 가능 (Go)** |
| **위험도 방어 (Red Team)** | 토론 중 "파일 삭제", "Git 푸시", "비밀키 조회" 언급 시 즉시 `PAUSED`(일시정지)로 자동 동결 | **위험 제로 (Go)** |

## 3. 실행 (Execute) — 전체 구현 과정 한눈에 보기

### ① D0: 실측 및 런타임 경쟁 치유 (Observation & Healing)
- **현상 진단**: Windows 환경에서 이전 워커가 종료된 직후 새 워커가 뜰 때 파일 락(Lock) 충돌로 `antigravity` 워커가 일시 중단되는 현상 진단.
- **자가 치유**: 독립적인 백그라운드 워커 프로세스를 안정화하여 브로커(PID 15480) 및 2/2 워커(`antigravity`, `claude`) 모두 정상 생존(`READY`, 종료 코드 0)을 실측으로 증명함.

### ② D1: 순수 상태 머신 (`c3p_absence_mode.py`)
- **6대 안전 방어선 구축**:
  1. **P2 절대 경계 감지**: 위험 명령어 감지 시 즉각 `PAUSED` 전환.
  2. **최대 발언 상한**: 5개 메시지 초과 시 강제 종료 (`NO_ACTIONABLE_CHANGE`).
  3. **시간 상한**: 15분(900초) 초과 시 자동 종료.
  4. **중복 주장 차단**: 이미 나왔던 의견의 해시(Hash)가 반복되면 즉시 토론 중단.
  5. **검증 실패 시 차단**: 단위 테스트 종료 코드가 0이 아니면 즉각 `BLOCKED`.
  6. **3단 결과 카드 의무화**: `무엇 / 왜 / 사용자 다음 행동` 필수 생성.

### ③ D2: 직관적인 CLI 명령어 연계 (`c3p_trigger.py`, `csc.py`)
- 발동문: `c3p 예산절약 모드`, `c3p 사용자부재 모드` (대소문자·공백 무관 인식).
- 오기동 방지: 단순 대화문(`"예산절약 모드를 논의하자"`)은 프로세스를 띄우지 않고 안전하게 거절.

## 5. [ELI10] 모르는 사람도 따라 하는 실전 사용법

### 💡 외출할 때 (모드 켜기)
터미널 창에 아래 명령 중 하나를 입력하면 즉시 켜집니다:
```bash
python csc.py trigger "C3P 사용자부재 모드"
```
또는
```bash
python csc.py trigger "C3P 예산절약 모드"
```
- **화면에 표시되는 내용**: 브로커와 워커가 0원 대기 상태로 전환되며, `{"status": "ready", "user_absence_mode": true}`가 출력됩니다.

### 🔍 현재 상태 확인할 때
```bash
python csc.py status
```
- **초록불 (`🟢 READY`)**: 브로커와 워커가 모두 조용히 살아있고 대기 중인 정상 상태입니다.

## 6. 전문용어 3단 병기 사전 (Glossary)

1. **토큰 (token, 인공지능에 글자를 보낼 때 소모되는 요금 단위)**: AI가 글을 읽고 쓸 때 세는 최소 글자 덩어리로, 외부 AI 호출 시 돈이 나가는 기준입니다.
2. **상태 머신 (state machine, 규칙에 따라 정해진 상태로만 바뀌는 프로그램 구조)**: 아무렇게나 움직이지 않고, 약속된 규칙에 따라서만 준비·실행·일시정지 상태를 오가는 통제 장치입니다.
3. **P2 절대 경계 (P2 boundary, 사람이 직접 허락해야만 실행할 수 있는 위험한 작업 목록)**: 소스코드 삭제, 패키지 설치, 깃 커밋·푸시처럼 시스템을 파괴하거나 외부에 영향을 주는 행동은 AI가 절대 단독으로 하지 못하게 막는 규칙입니다.
4. **유한 토론회 (bounded deliberation, 발언 횟수와 시간에 엄격한 끝이 있는 회의)**: AI끼리 끝없이 말을 주고받는 것을 막기 위해 최대 5번의 말과 15분이라는 명확한 마감선을 두고 결과를 도출하는 방식입니다.
5. **워커 (worker, 뒤에서 조용히 심부름을 해주는 백그라운드 프로그램)**: 사용자의 대화창을 방해하지 않고 컴퓨터 안에서 메시지를 실시간으로 전달해 주는 조수 프로그램입니다.
