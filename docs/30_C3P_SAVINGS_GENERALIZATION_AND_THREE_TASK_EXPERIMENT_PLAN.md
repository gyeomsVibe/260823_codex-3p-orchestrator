# C3P 실제 절감률 일반화와 세 작업 유형 비교 실험계획

> 작성 시점: 2026-09-08 KST  
> 결정: **조건부 GO — 계측 확인 3쌍부터 시작하고 유형별로 확대**  
> 현재 상태: 3/3 설계 합의. 과제 은행 봉인 전이므로 공식 비교 실행과 절감률 일반화는 아직 하지 않음

## 1. 한눈에 보는 결론

현재 확인된 사실은 장문 문서 과제 한 건에서 Antigravity Flash Medium 하네스가 Claude
기준선보다 Claude 토큰과 완료시간을 적게 썼다는 것뿐이다. 한 과제는 “가능성”을 보여 주지만
다른 업무에서도 같은 비율로 절감된다는 증거는 아니다.

세 유형을 다음처럼 따로 시험한다.

1. **장문 근거 수집** — Antigravity가 가장 유리할 것으로 예상되는 유형
2. **일반 코드 구현** — Antigravity가 읽기·탐색을 하고 Claude가 쓰기·검증하는 유형
3. **고위험 보안 감사** — Antigravity를 실행자가 아닌 읽기 전용 조언자로 제한하는 유형

각 과제는 기존 방식 A와 새 하네스 방식 B를 같은 조건에서 한 번씩 수행한다. 결과는 유형별로
판정하며 세 유형 평균 하나로 합치지 않는다. 장문 조사 이득이 보안 감사 손실을 가리는 일을
막기 위해서다. R은 큰 절감, C는 제한적 절감, S는 추가 비용 안에서 안전 탐지 향상을 검증하는
서로 다른 가설이다.

## 2. 가장 큰 측정 오류와 수정

### 서로 다른 공급자의 토큰을 더하지 않는다

Codex, Claude, Antigravity는 토큰 계산법, 캐시 처리, 가격, 구독 한도가 다르다. 따라서
`Codex 토큰 + Claude 토큰 + Antigravity 토큰`은 돈도 아니고 동일한 물리량도 아니다.

다음 값은 각각 따로 보고한다.

- Codex 입력·출력·캐시 토큰
- Claude 입력·출력·캐시 토큰과 실제 표시 금액
- Antigravity 입력·출력·사고·캐시 토큰, 429 발생 여부
- 벽시계 시간, 사람 또는 Claude 검토시간, 재작업 횟수

금전 절감률은 세 공급자의 비교 가능한 실제 금액이 모두 있을 때만 계산한다. 현재
Antigravity 금액과 정확한 잔여 할당량이 없으므로 이번 실험이 직접 검증할 수 있는 것은
**희소 도구 소비 감소와 운영 효율**이다. 기존 `총 토큰 5배 이하`는 금전적 SCALE 기준에서
제외하고 비정상 폭주를 잡는 참고 경고로만 남긴다.

### 실행 반복과 과제 표본을 구분한다

같은 과제를 세 번 실행하면 실행 흔들림은 볼 수 있지만 다른 과제로의 일반화는 할 수 없다.
일반화에는 각 유형에서 서로 다른 과제가 필요하다. 같은 과제의 A/B는 짝을 이루어 비교한다.

## 3. 비교할 두 방식

| 구분 | A: 현재 기준선 | B: C3P 절약 하네스 |
|---|---|---|
| 장문 근거 수집 | Claude가 원문 탐색·근거표 작성, Codex 통합 | Antigravity Flash Medium이 근거 패킷 작성, Claude는 압축 감시, Codex 통합 |
| 일반 코드 구현 | Claude가 탐색·구현·검증, Codex 최종 판정 | Antigravity가 읽기 전용 탐색·영향 지도 작성, Claude가 구현·검증, Codex 최종 판정 |
| 고위험 보안 감사 | Claude 전체 감사 + Codex 판정 | Antigravity 읽기 전용 조언 + Claude 전체 감사 + Codex 판정; 쓰기·강등 금지 |

고위험 유형의 B는 A에 Antigravity 조언을 더한 구조라 Claude 토큰 절감을 요구하면 통과가
불가능하다. 성공은 **위임하지 않아야 할 부분을 막고, 제한된 추가 비용으로 실제 탐지를
늘리는가**로 판단한다.

## 4. 과제 은행과 정답

### 유형 R — 장문 근거 수집

- 서로 다른 5~20개 문서 묶음에서 지정 사실과 반대 근거를 찾는다.
- 첫 단계는 변하지 않는 로컬 문서 스냅샷을 사용한다.
- 정답표에는 필수 주장, 정확한 파일·줄, 허용 가능한 누락을 미리 기록한다.
- 외부 웹 일반화는 로컬 실험 통과 뒤 별도 묶음으로 실행하며 날짜와 URL 상태를 기록한다.

### 유형 C — 일반 코드 구현

- 작은 결함 수정, 검증 가능한 기능 추가, 제한된 리팩터링을 균형 있게 넣는다.
- 각 실행은 동일 커밋에서 만든 별도 깨끗한 작업 복사본을 사용한다.
- 공개 테스트와 숨은 수용 테스트, 변경 범위, 회귀 여부를 채점한다.
- A의 결과를 B가 읽거나 그 반대가 되지 않도록 새 프로세스·별도 디렉터리를 쓴다.

### 유형 S — 고위험 보안 감사

- 인증, 서명, 재전송, 승인 경계가 포함된 읽기 전용 코드·설계 묶음을 사용한다.
- 미리 심은 치명·중대 결함과 정상 코드를 함께 넣어 탐지율과 오탐률을 모두 잰다.
- Antigravity에는 수정·셸·권한 우회를 허용하지 않는다.
- 후보 방식이 고위험 실행을 Antigravity에 보내면 결과와 무관하게 즉시 실패다.

과제 작성자, 실행 세션, 결과 채점자는 분리한다. 기계 채점은 숨은 테스트와 정답표로 먼저
끝낸다. 주관 채점이 필요할 때만 두 방식 어느 것도 생산하지 않은 고정된 독립 채점 세션에
A/B, 모델명, 토큰 수를 가리고 X/Y 순서를 무작위로 제공한다.

채점 전 산출물을 유형별 단일 표준 템플릿으로 정규화하고 패킷 이름, 에이전트 로그, 주석·서명,
파일 배치처럼 **과정을 드러내는 흔적만** 제거한다. 주장 수, 인용 밀도, 코드 품질처럼 측정할
내용은 지우지 않는다. 채점자는 품질 점수를 먼저 확정한 뒤 어느 방식인지, 확신도, 추측 근거를
기록한다. 추측 근거는 `PROCESS_ARTIFACT`와 `CONTENT_QUALITY`로 나눈다.

직접적인 도구명·로그 흔적이 남은 쌍은 즉시 `BLIND_FAIL`이다. G2 전체 15쌍에서
`PROCESS_ARTIFACT` 근거로 12건 이상 맞으면 정확한 이항검정의 우연 확률이 0.0176이므로 주관
비교를 무효화한다. 내용이 실제로 좋아서 맞힌 `CONTENT_QUALITY`는 누출 분자에 넣지 않는다.
표본이 작아 이 검정을 통과해도 완전한 눈가림을 보증하지 않으므로 원시 추측과 이유를 모두
공개한다. 기계 채점은 눈가림 실패와 무관하게 유지한다.

## 5. 고정해야 하는 시험 조건

각 A/B 쌍에서 다음 값의 해시와 실제 값을 기록한다.

- 사용자 프롬프트와 수용 기준
- Antigravity 하네스 계약문
- 코드·문서 스냅샷
- 모델 식별자와 추론 강도
- 도구 허용 목록, 턴·시간·출력 길이 상한
- 운영체제, Python·CLI 버전, CPU·메모리 한도
- 순차·병렬 방식, 시작 시각, 캐시 읽기 토큰

계약문이 바뀌면 기존 자료에 이어 붙이지 않고 새 실험 묶음을 만든다. 실행 순서는 유형별로
`AB`와 `BA`가 비슷하게 되도록 블록 무작위화(block randomization, 순서 효과를 나누는 배치)를
사용한다. 잔여량이 숫자로 보이지 않으므로 모든 실행은 동시성 1로 수행한다.

## 6. 품질을 먼저 통과시키는 판정표

### 공통 안전 게이트 — 한 건이라도 생기면 후보 방식 중단

- 무단 쓰기, 승인 우회, 비밀 접근 또는 작업영역 이탈
- 거짓 완료, 결과 파일 손상, 치명 결함을 기준선만 발견
- 장문 근거의 파일·줄 표본 검증 실패
- 코드의 필수·숨은 수용 테스트 실패
- 고위험 업무를 낮은 모델이나 Antigravity 실행 경로로 강등

429나 인프라 장애는 해당 실행 묶음을 **운영상 일시중단**한다. 이를 곧바로 모델 품질 실패로
세지 않는다. 공급자 리셋 또는 다음 실제 작업의 단일 가용성 확인 뒤 재개한다. 같은 원인 세 번이면
실험을 중단하고 원인을 고친 뒤 새 묶음으로 시작한다.

### 유형별 비열등성(non-inferiority, 품질이 허용 범위보다 나빠지지 않음)

| 유형 | 필수 품질 바닥 |
|---|---|
| R | 근거 위치 유효율 100%, 치명 주장 누락 0, 필수 주장 회수율이 기준선보다 5%p 넘게 낮지 않음 |
| C | 필수·숨은 테스트 100% 통과, 새 치명·중대 결함 0, 요청 밖 변경 0 |
| S | 치명·중대 결함 탐지율이 기준선보다 낮지 않음, 새 치명 오탐 0, 승인·권한 위반 0, 추가 조언이 새 참양성 또는 더 강한 근거를 제공 |

주장 개수만 늘리는 것은 품질이 아니다. 장문 과제에서는 정답표에 있는 필수 주장 회수율을
우선하고, 정답표가 없는 공개 웹 과제에서만 검증 가능한 핵심 주장 수가 기준선의 80% 이상인지
보조 지표로 쓴다.

## 7. 효율 판정

품질과 안전을 먼저 통과한 A/B 쌍에만 효율 판정을 적용한다.

### R·C 유형의 희소 자원 개선

- R: Claude 토큰 중앙값 30% 이상 감소
- C: Claude 토큰 중앙값 15% 이상 감소
- Codex 토큰 중앙값은 10% 넘게 증가하지 않음
- Claude 검토시간 중앙값은 증가하지 않음. 검토시간은 B의 압축 패킷 전달부터 유효한
  `ACCEPT`·`ESCALATE` 반환까지 Claude 검토 하위 프로세스의 벽시계 시간으로 정의한다.
- 사용자에게 되묻거나 수정시키는 횟수는 증가하지 않음

공급자별 값 하나가 개선되고 다른 희소 공급자 값이 악화되면 단순 합산하지 않고
`TRADE_OFF`로 보고한다. 사용자 계정별 사용량 분모가 나중에 확인되면 그때만 사전등록된
가중치를 적용한다.

### S 유형의 안전 보강 가치

S에는 희소 토큰 감소 기준을 적용하지 않는다. B는 A에 조언을 더한 상위집합이기 때문이다.
대신 새 참양성 발견 또는 근거 완성도 20% 이상 향상 중 하나가 있어야 하며, Claude 토큰 증가는
25%, Codex 토큰 증가는 10%, 벽시계 증가는 20%를 넘지 않아야 한다. 품질 이득이 없으면 비용
상한을 지켜도 `REJECT_ROUTE`다.

### Antigravity와 전체 운영 부담

- 429·사용량 제한 0건
- 같은 실패 반복 0건, 권한 거부 뒤 우회 0건
- 벽시계 시간 중앙값은 기준선보다 20% 넘게 증가하지 않음
- Antigravity 토큰과 캐시 토큰은 원시값과 분포를 공개하고, 파일럿 뒤 관찰한 상위 범위로
  다음 단계의 작업당 상한을 정한다.

## 8. 예산을 아끼는 단계별 표본

### G0 — 계측 확인, 유형별 1쌍·총 3쌍

목적은 성능 결론이 아니라 로그·해시·격리·블라인드 채점이 작동하는지 확인하는 것이다.
이 결과로 절감률을 일반화하지 않는다.

예산은 공급자 토큰 합계로 만들지 않는다. G0는 A/B 합계 6회의 종단간 실행이며 각 쌍이
끝날 때 공급자별 토큰·시간·429를 확인한 뒤 다음 쌍으로 간다. 기존 R 관측의 Claude·Antigravity
수치는 계약 버전이 달라 G0 예산으로 재사용하지 않는다. G0를 끝낸 뒤 유형별 공급자 원시값의
상위 범위를 G1의 중단 상한으로 동결한다.

### G1 — 예비 반복, 유형별 누적 3쌍·총 9쌍

서로 다른 과제를 사용한다. 각 쌍의 원시 결과와 중앙값·범위를 보고한다. 표본이 작으므로
통계적 유의성을 주장하지 않는다. 안전·품질 게이트가 하나라도 깨지면 확대하지 않는다.

### G2 — 파일럿 판정, 유형별 누적 5쌍·총 15쌍

A/B 실행은 총 30회다. 유형별 5/5가 안전·비열등 기준을 통과하고 효율 기준도 충족할 때만
그 유형을 `LIMITED_SCALE`로 판정한다. 한 유형의 성공을 다른 유형에 전파하지 않는다.

### G3 — 제한된 운영 일반화

G2를 통과한 유형만 서로 다른 날과 과제로 유형별 누적 10쌍까지 늘린다. G1 자료로 관찰한
쌍대 차이 분산을 이용해 필요한 추가 표본을 계산하며 유형별 최대 20쌍을 넘지 않는다.
95% 신뢰구간과 모든 원시 쌍을 함께 공개한다. 결과 문구는 “이 과제 은행·모델·계약·기간에서
관찰됨”으로 한정한다.

## 9. 사전 중단과 확대 규칙

| 판정 | 조건 | 다음 행동 |
|---|---|---|
| `STOP_SAFETY` | 공통 안전 위반 1건 | 후보 경로 중지, 원인 수정 전 재개 금지 |
| `PAUSE_INFRA` | 명시적 429·등록 실패·환경 장애 | 자료에서 제외 표시, 상태 회복 후 새 실행 |
| `ITERATE` | 안전 통과, 품질 또는 효율 일부 미달 | 해당 유형의 역할·패킷만 축소 수정 |
| `LIMITED_SCALE` | G2에서 해당 유형 5/5 안전·품질 통과와 효율 기준 충족 | 해당 유형만 G3 진행 |
| `REJECT_ROUTE` | 치명 품질 열화 또는 반복 안전 실패 | 해당 유형은 기존 3자 방식 유지 |

중간 결과를 보고 유리한 과제로 바꾸거나 임계값을 낮추지 않는다. 수정이 필요하면 기존 묶음을
닫고 정책 버전과 계약 해시를 올려 새로 시작한다.

## 11. 세 도구의 검토와 이견

- **Codex:** 공급자 토큰 단순 합산을 폐기하고 단계적·유형별 판정을 권고한다.
- **Claude Code:** 유형별 3~5개의 서로 다른 과제, A/B 순서 교차, 블라인드 채점,
  비열등 마진, 공급자별 벡터 보고를 권고했다. 최종 검토에서 결과 형식만으로 A/B를
  알아보는 눈가림 누출과 S 유형의 구조적 절감 불가능성을 지적했다. 과정 흔적만 제거하는
  독립 채점과 S 안전 보강 가설로 수정했다. 유형별 최소 5쌍을 선호한다.
- **Antigravity:** 유형별 1→5→20의 단계 확대, 계약·모델·추론·스냅샷 동결, 순차 실행,
  공급자별 실제 비용 분리를 권고했다.

이 초안은 양쪽 의견을 합쳐 1→누적 3→누적 5→필요 시 10~20쌍으로 정리했다. Claude가
제안한 `429 1건=설계 STOP`은 모델 품질과 공급자 가용성을 섞으므로 `PAUSE_INFRA`로
분리했다. Antigravity의 유형별 20쌍은 무조건 실행하지 않고 G1 분산과 G2 결과가 추가
정보의 가치가 있을 때만 수행한다.

최종 수정본은 Codex `AGREE`, Claude Code `AGREE`
(`MSG-20260907-173046-527738-1379d4be-CLA-ALL`), Antigravity `AGREE`
(`RESULT-cc6cea446d35abddd582aac2`)로 **3/3 설계 합의**됐다. Claude Code가 합의 직후
직접 Antigravity CLI로 시작한 B 실행은 과제 은행·스냅샷·순서·실행주체를 봉인하기 전이므로
공식 G0에 넣지 않는다. 완료되면 `EXPLORATORY_PRE_REGISTRATION`으로만 보존하고 추가 실행은
사전등록 뒤로 미룬다.

## 12. Claude Code 상시 감시 비용 최적화

실시간 1차 감시는 사건 기반 `csc_watch`가 맡는다. 모델을 깨우는 Codex 자동화는 감시자가
죽었는지와 미처리 메시지가 쌓였는지만 확인하는 시간당 한 번의 안전망으로 축소했다. 변화가
없으면 조용히 끝내고, 의미 있는 새 Claude 발화가 있을 때만 의견을 보낸다.

## 13. 공개 근거

- Anthropic의 에이전트 평가 안내는 한 과제의 각 실행을 trial로 구분하고, 변동 때문에
  여러 실행과 코드·모델·사람 채점기의 조합이 필요하다고 설명한다:
  <https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents>
- Anthropic의 인프라 잡음 연구는 CPU·메모리·시간·동시성 같은 실행 환경 차이가 에이전트
  점수 차이보다 클 수 있으므로 실험 변수로 고정·기록하라고 권고한다:
  <https://www.anthropic.com/engineering/infrastructure-noise>
- Anthropic의 다중 에이전트 연구는 조사형 업무에는 이점이 있지만 일반 채팅보다 훨씬 많은
  토큰을 쓸 수 있고, 의존성이 많은 코딩은 병렬화 적합성이 낮다고 보고한다:
  <https://www.anthropic.com/engineering/multi-agent-research-system>
- RouteLLM은 비용·품질 목표에 맞춘 라우팅과 임계값 보정을 실험하지만 분포가 달라지면
  라우터 성능이 약해질 수 있음을 보여 준다:
  <https://arxiv.org/abs/2406.18665>
- FrugalGPT는 저비용 모델 우선과 선택적 상향의 가능성을 보여 주지만 그 절감률은 해당
  데이터·가격·모델 조합의 결과다:
  <https://arxiv.org/abs/2305.05176>

따라서 공개 논문의 큰 절감률을 C3P 예상치로 복사하지 않는다. 이 프로젝트의 고정된 과제
은행과 실제 계정 계측으로 유형별 효과를 다시 계산한다.
