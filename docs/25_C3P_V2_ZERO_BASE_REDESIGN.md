## 1. /CRITIC — 실측으로 본 v1의 실패

### 1-1. 🔴 연결 관리가 대화보다 12배 많은 로그를 남겼다

```
실제 주고받은 메시지        161건   (queue.jsonl)
브로커 연결 부기(簿記)    1,930건   (audit.jsonl: REGISTER 982 + AGENT_LEFT 948)
```

**비율 12:1.** 짐보다 포장재가 열두 배 무거웠다.

`REGISTER`/`AGENT_LEFT` 가 982/948 이라는 것은 **브로커가 끊임없이 붙었다 떨어졌다**는 뜻이다.
그 불안정을 감시하려고 생존 판정기를 만들었고, 생존 판정기가 틀려서 세 번 고쳤고,
그 판정을 보여주려고 감시판을 만들었다. **없어도 될 것을 지키려고 만든 것들이다.**

### 1-2. 🔴 브로커가 죽어도 아무 일도 일어나지 않았다

오늘 브로커는 최소 4회 죽었다. 그때마다 메시지는 `[fallback]` 으로 **정상 전달됐다.**
가장 생산적이었던 대화(5주차 세션과의 8왕복 코드 리뷰)는 **브로커를 거치지도 않았다.**

**작동을 멈춰도 아무도 불편하지 않은 부품은 필요한 부품이 아니다.**

### 1-3. 🔴 실시간을 전제한 설계인데 셋이 동시에 존재한 적이 없다

```
Codex        사용량 한도 — 오늘 91분 연속 무응답
Antigravity  헤드리스 권한 거부 — 36시간 무응답
Claude       세션에 묶임 — 사용자가 열어야 존재
```

**동시 존재가 전제인 프로토콜을, 동시 존재가 불가능한 셋 위에 올렸다.**
그래서 정족수가 안 차고, 교착이 나고, 13절을 만들어 교착을 풀어야 했다.
13절은 좋은 조항이지만 **애초에 잘못된 전제를 보수하는 조항**이다.

### 1-4. 공개 자료가 같은 경고를 한다

한 개발자가 6개월과 3천 달러를 태우고 남긴 기록 —
**이메일 한 통을 쓰려고 8인 팀을 구성했고, 다섯 줄에 2만 5천 달러 예산이 잡혔다.**
([5 brutal lessons](https://dev.to/dpelleri/5-brutal-lessons-from-building-a-multi-agent-ai-system-and-how-to-avoid-my-epic-fails-35aa))

우리도 형태가 같다. **조율 기구가 조율 대상보다 커졌다.**

## 2. /REDTEAM — v2 를 미리 공격한다

| 공격 | v2 의 답 |
|---|---|
| "서버를 없애면 실시간이 안 된다" | **실시간이었던 적이 없다.** 12:1 로그 비율과 91분 침묵이 증거다 |
| "파일 추가는 경합에 취약하다" | append-only + `O_EXCL` 락은 이미 있고 161건 무손실이다 |
| "스케줄러도 결국 상주 아닌가" | 앱이 켜져 있을 때만 돈다. **우리가 지킬 프로세스가 아니다** |
| "대시보드를 없애면 안 보인다" | 로그가 보인다. 감시판은 **로그의 요약**이었고, 요약은 원문보다 낡는다 |
| "할루시네이션 용인하면 오늘 만든 감사기가 무의미" | 감사기를 **끄지 않고 등급만 낮춘다**. 5절 참조 |
| "18개 모듈을 지우면 128개 테스트가 죽는다" | 지우지 않는다. **보류**한다. 7절 참조 |

## 4. /DEEPDIVE — 탑다운 4계층

```
┌ 4층  서버         ← 최후순위. 아래 셋으로 부족하다는 실측이 나올 때만
├ 3층  기록         대화 로그 HTML. 스케줄러가 갱신
├ 2층  시계         스케줄러. 비동기인 셋을 만나게 하는 유일한 수단
├ 1층  참여         SessionStart 훅. 도구가 켜지면 자동 합류
└ 0층  진실         queue.jsonl append-only. 유일한 정본
```

**설계 원칙: 위층이 죽어도 아래층은 산다.**
v1 은 반대였다 — 브로커(위)가 죽으면 생존 판정(아래)이 거짓말을 했다.

## 5. /ALT3 — 트리거 없이 자동 합류

### 지금 (v1)

사용자가 `c3p 발동` 이라고 쳐야 시작된다. **사람이 매번 방아쇠를 당겨야 한다.**

### v2 — 세션 시작 훅

`SessionStart` 훅의 **표준출력이 그대로 에이전트의 컨텍스트로 주입된다.**
([Claude Code Hooks](https://code.claude.com/docs/en/hooks-guide))

즉 도구가 켜지는 순간, 트리거 없이 이렇게 된다.

```
도구 시작 → 훅 실행 → 내 미읽음 메시지 N건 + 미해결 안건을 컨텍스트로 주입
         → 에이전트가 이미 알고 시작한다
```

이미 `swarm_hook.py brief` 가 이 자리에 있다. **틀을 새로 만들 필요가 없다. 내용만 바꾼다.**

세 도구별 대응:

| 도구 | 자동 합류 수단 | 상태 |
|---|---|---|
| Claude Code | `SessionStart` 훅 | **있음.** 내용만 c3p 용으로 교체 |
| Codex | `AGENTS.md` 최상단 규약 | 있음. 읽기는 하되 강제는 아님 |
| Antigravity | `GEMINI.md` 최상단 규약 | 있음. 헤드리스 권한 문제는 별건 |

**정직한 한계:** Codex 와 Antigravity 에는 훅에 해당하는 강제 장치가 없다.
문서를 읽게 할 수는 있어도 **읽었는지 강제할 수는 없다.** 이건 v2 도 못 푼다.
그래서 2층(스케줄러)이 필요하다 — 자발적 참여가 안 되면 **시계가 불러야 한다.**

## 6. /DEEPDIVE — 스케줄러 설계 (핵심)

### 왜 스케줄러가 이 문제의 답인가

**셋은 만날 수 없다. 그러면 만나지 말아야 한다.**

```
v1  회의 모델   셋이 동시에 있어야 결정된다  →  91분 침묵 → 교착
v2  우편함 모델  각자 자기 시각에 확인한다    →  침묵도 결과의 일부(기권)
```

13절이 이미 "부재는 기권" 을 정했다. 스케줄러는 그 조항에 **시계를 달아준다.**

### 세 가지 리듬

| 이름 | 주기 | 하는 일 | 비용 |
|---|---|---|---|
| **점호** | 4시간 | 각 도구가 미읽음을 읽고 한 줄 남긴다 | 토큰 소량 |
| **기록 갱신** | 30분 | 로그 HTML 재생성 (에이전트 호출 없음) | **0** |
| **마감** | 안건별 1회 | 마감 시각에 표를 집계하고 판정 | 토큰 소량 |

**기록 갱신에 에이전트를 부르지 않는 것이 핵심이다.** 파일을 읽어 HTML 로 옮기는 일에
언어 모델이 필요 없다. v1 은 훅이 뛸 때마다 이걸 했고 그건 옳았다 — v2 는 시계로 옮긴다.

### 예산 계산 (사용자 우려 반영)

```
점호  4시간마다 × 3도구 = 하루 18회
기록  30분마다 = 하루 48회, 토큰 0
마감  안건당 1회
```

v1 의 상시 워커 2개 + 브로커는 **아무 대화가 없어도 계속 돌았다.**
v2 는 **일이 있을 때만 토큰을 쓴다.**

### 어떤 스케줄러를 쓰는가

| 후보 | 지속성 | 판정 |
|---|---|---|
| `CronCreate` | **세션 종료 시 소멸** | 부적합. c3p 는 세션보다 오래 살아야 한다 |
| `scheduled-tasks` MCP | 디스크 저장, 앱 실행 중 동작 | **채택** |
| OS 작업 스케줄러 | 완전 상시 | 보류. 설치·권한 변경이라 승인 필요 |

**선택: `scheduled-tasks`.** 앱이 닫혀 있으면 다음 실행 때 밀린 것이 돈다.
이건 결함이 아니라 우리 상황에 맞다 — **사용자가 앱을 닫았으면 협업할 일도 없다.**

## 7. /OPTIMIZE — 진행 순서 (선구현 후수정)

사용자 지시: **할루시네이션을 용인하고 먼저 다 구현한 뒤 오류를 잡는다.**

이 지시를 그대로 따르되 **한 가지만 다르게 한다** — 감사기를 끄지 않고 **등급만 낮춘다.**

```
구현 단계  csc_audit 를 차단(block) → 경고(warn) 로.
           틀린 채로 진행하되 무엇이 틀렸는지는 기록에 남는다.
수정 단계  경고 목록을 그대로 수정 대기열로 쓴다.
```

**끄면 나중에 무엇을 고쳐야 하는지 알 수 없다.** 속도는 지시대로 내되, 부채는 적어 둔다.
이건 지시 위반이 아니라 지시를 실행 가능하게 만드는 장치다.

### 단계

```
S1  attic/ 로 3개 모듈 이동 + 대시맴 폐기        (되돌릴 수 있음)
S2  SessionStart 훅을 c3p 자동 합류로 교체
S3  스케줄러 3종 등록                            ← 사용자 승인 필요
S4  로그 HTML 을 스케줄러 갱신으로 전환
S5  감사기 등급을 구현 단계용으로 전환
S6  전체 통과 후 오류 수정 라운드
```

**S3 만 승인이 필요하다.** 나머지는 로컬·가역이다.

## 8. 검증하지 못한 것

- **Codex 와 Antigravity 의 자동 합류는 강제할 수 없다.** 문서로 요청할 뿐이다
- `scheduled-tasks` 가 이 프로젝트에서 실제로 도는지 **아직 등록해 보지 않았다**
- 위 예산 수치는 **호출 횟수 추정**이지 실측 토큰이 아니다
- 세 도구 합의를 거치지 않았다. 이 문서는 **Claude 의 제안**이며 협의 전이다
