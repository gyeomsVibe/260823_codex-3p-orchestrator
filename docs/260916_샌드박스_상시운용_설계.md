# Codex Windows 샌드박스 영구 운영 설계

- 작성·재검토: 2026-09-16
- 목표: 일반 개발 작업은 샌드박스 안에서 계속 수행하고, Git 메타데이터 경계 때문에 전체 보호를 해제하지 않는다.

## 권고안

기본 작업은 내장 `:workspace` 권한 프로필을 유지한다. 예약 ACL 삭제는 폐기하고 읽기 전용 감사만 유지한다. Git 쓰기는 자동 검토 또는 사용자 승인을 거치는 별도 경계 작업으로 취급한다.

이 조합은 일반 파일 작업의 연속성과 샌드박스 경계를 함께 보존한다. `gitops`의 `danger-full-access`를 기본 경로로 삼거나, `git` 전체를 항상 허용하는 규칙을 두면 작업 범위 밖 파일·네트워크·파괴적 Git 명령까지 함께 열릴 수 있다.

## 3개 대안 비교

| 대안 | 장점 | 비용·위험 | 선택 |
|---|---|---|---|
| A. 네이티브 Windows `:workspace` + 읽기 전용 ACL 감사 + 승인된 Git 경계 | 현재 환경을 유지하고 보호 경계를 보존 | Git 단계에서 경계 검토 필요 | **적용 완료** |
| B. 사용자 정의 Permissions Profile | 파일·네트워크 규칙을 더 세밀하게 관리 | 베타 기능이며 Windows 절대 경로 읽기 예외가 이번 실측에서 작동하지 않음 | 보류 |
| C. WSL2의 Linux 샌드박스 | NTFS ACL 기반 Git 경계 문제를 피함 | 도구체인·경로·성능·Windows 전용 빌드 호환성 검증 필요 | Git 자동화가 핵심일 때 후보 |

VHDX·Dev Drive는 저장공간 격리 수단일 수 있지만 `.git` 보호 정책 자체를 해결한다고 검증되지 않아 우선 대안에서 제외한다.

## 운영 흐름

1. 일반 편집·테스트는 `:workspace`에서 수행한다.
2. Git 전에는 `git status --short`로 소유권이 분명한 경로만 고른다.
3. `git fetch` 후 로컬과 원격이 갈라졌으면 자동 병합·rebase·force push를 하지 않는다.
4. 사용자가 승인한 경우에만 선택 경로를 stage·commit·push한다.
5. push 후 `HEAD`와 `origin/<branch>`를 비교한다.

## ACL 감사

`tools/codex-sandbox-acl.ps1`은 루트와 `.git`의 명시적 SID ACE를 읽고 다음 수치만 남긴다.

```text
mode=Check targets=... sid_candidates=... ledger_backed=... unclassified=... deny=...
```

- `ledger_backed`: Codex의 `cap_sid` ledger에 등록된 SID 후보
- `unclassified`: 현재 ledger에서 찾지 못한 후보. 삭제 가능 판정이 아니다.
- 종료 코드 0: 감사 완료. SID 후보는 보고 자료이며 실패로 취급하지 않음
- 종료 코드 3: 폐기된 `-Mode Clean` 요청을 안전하게 거부함

`CodexSandboxUpdateMaintenance` 예약 작업은 로그온 시점과 30분마다 `Check`를 실행한다. Codex 버전이나 Windows 빌드가 달라지면 샌드박스 경계 검사 7개도 다시 실행한다. 버전이 같아도 24시간마다 전체 검사를 반복한다. 앱 컨테이너에 따라 `%LOCALAPPDATA%` 로그가 패키지 경로로 리디렉션될 수 있으므로, 로그 위치만으로 실행 실패를 단정하지 않는다.

같은 실행기가 `%TEMP%\codex-git-ignore\ignore`도 자기복구한다. 원본은 사용자 Git ignore 파일 하나뿐이며 Git config·인증정보는 복사하지 않는다. 해시가 같으면 다시 쓰지 않는다.

Git 경계 규칙의 정본은 `config/codex/sandbox-git-boundary.rules`다. 유지관리 작업은 전역 규칙 파일이 없거나 달라졌을 때 기존 파일을 로컬 백업한 뒤 정본을 복원한다. 사용자 `config.toml`과 Windows ACL은 자동 수정하지 않는다.

## 설정 정규화 적용 상태

공식 Permissions 문서는 `default_permissions`/`[permissions]`와 `sandbox_mode`/`[sandbox_workspace_write]`를 함께 쓰지 말라고 명시한다. 현재 사용자 설정은 다음과 같이 정규화했다.

```toml
approval_policy = "on-request"
default_permissions = ":workspace"
approvals_reviewer = "auto_review"
```

`sandbox_mode`와 `[sandbox_workspace_write]`는 제거했다. Git 경계 규칙은 사용자 설정의 `rules/sandbox-git-boundary.rules`에 있으며, 변경 전 설정 백업은 사용자 `.codex/backups/` 아래에 보존한다.

설정 변경은 새 Codex 작업이나 앱 실행 환경 갱신 후 완전히 반영된다.

## 반증 조건과 남은 미확인 사항

- OpenAI가 승인된 저장소에 한정한 Git broker 또는 `.git` 쓰기 권한을 공식 제공하면 A안의 별도 경계 절차를 단순화할 수 있다.
- `.git` 직접 쓰기는 새 프로필에서도 의도대로 차단된다. 좁은 Git broker가 제품에 추가되기 전까지 승인 경계가 필요하다.
- 사용자 정의 프로필의 Windows 홈 절대 경로 읽기 예외는 설정이 로드돼도 실측상 적용되지 않았다.
- WSL2 전환의 Windows 전용 도구 호환성과 실제 성능은 아직 미측정이다.
- 과거 삭제된 ACE가 정상 capability ACE였는지 사후에 완전히 복원·증명할 자료는 없다.
