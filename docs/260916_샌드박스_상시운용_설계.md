# 샌드박스 상시 운용 설계 — 주기 점검과 영구 개선 로직

- 작성: 2026-09-16
- 목표: Codex 샌드박스를 항상 켜 둔 채로, 권한 거부 때문에 작업이 막히지 않게 한다
- 전제: `sandbox_mode = "workspace-write"` 고정, `[windows] sandbox = "elevated"`

---

## 1. 무엇이 문제인가 (실측)

샌드박스를 켜고 한 번 실행한 직후 측정한 결과다.

| 항목 | 결과 |
|---|---|
| `git status` | 성공 |
| `git fetch origin` | 성공 |
| 작업 폴더 쓰기 | 성공 |
| **`.git` 폴더 쓰기** | **거부** (`Access to the path ... is denied`) |
| 실행 1회로 새로 쌓인 권한 항목 | 저장소 루트 1건, `.git` 2건(거부 2건) |

작업 폴더 전체를 훑었더니 저장소 16곳에서 찌꺼기 **39건(거부 26건)**이 나왔다. 이 프로젝트만의 문제가 아니었다.

**핵심 구분**

- `.git` 쓰기 거부는 **설계 동작**이다. 샌드박스가 git 이력을 보호하려고 일부러 막는다. 청소해도 없어지지 않는다.
- 권한 항목이 **무한히 쌓이는 것**은 버그다. 종료할 때 지우지 않아서 실행할수록 늘어난다. 이건 청소로 해결한다.

---

## 2. 3계층 설계

### 1계층 — 자동 청소 (구현 완료)

작업 폴더 안의 Git 저장소를 자동으로 찾아 찌꺼기 권한을 지운다. 새 저장소를 만들어도 따로 등록할 필요가 없다.

| 구성 요소 | 내용 |
|---|---|
| 점검·정리기 | `tools/codex-sandbox-acl.ps1` (`-Mode Check` / `-Mode Clean`) |
| 스케줄러 실행기 | `tools/codex-sandbox-acl-task.ps1` (저장소 자동 탐색, 깊이 2단계) |
| 예약 작업 | `CodexSandboxAclCleanup`, 30분 간격 |
| 로그 | `%LOCALAPPDATA%\codex-sandbox-acl.log` — 실행마다 한 줄 |

`icacls`로는 지워지지 않는다. 계정이 삭제된 뒤라 이름을 찾을 수 없어 오류 1332가 난다. 그래서 SID를 직접 다룬다.

### 2계층 — 상태 감시

로그 한 줄의 형식은 다음과 같다.

```
2026-09-16 15:19:27 mode=Clean targets=32 stale=39 deny=26
```

- `stale` 값이 계속 커지면 청소 주기가 짧아져야 한다는 신호다.
- `mode=Check`에서 `stale`이 0이 아니면 종료 코드 1이 나오므로 다른 점검 도구에 물리기 쉽다.
- 수동 점검: `pwsh -NoProfile -File tools\codex-sandbox-acl.ps1`

### 3계층 — git 쓰기 작업 경로 (선택 필요)

샌드박스를 켜 둔 이상 `.git` 쓰기는 계속 막힌다. 커밋·푸시를 하려면 셋 중 하나를 골라야 한다.

| 방식 | 내용 | 대가 |
|---|---|---|
| **가. 사람이 git 실행** | Codex는 파일만 고치고, 커밋·푸시는 사용자가 직접 한다 | 손이 한 번 더 간다. 승인 설정을 건드리지 않는다 |
| **나. 전용 프로필** | `~/.codex/config.toml`에 `[profiles.gitops]`를 만들고 `sandbox_mode = "danger-full-access"`로 둔 뒤, git 작업할 때만 `codex --profile gitops` | 그 프로필에서는 샌드박스가 없다 |
| **다. 부분 승인** | `approval_policy`를 `{ granular = { sandbox_approval = true } }`로 바꿔, 샌드박스 탈출이 필요할 때만 승인 창을 띄운다 | 승인 창이 가끔 뜬다 |

현재는 **가** 상태다. 나·다는 사용자가 직접 설정해야 한다.

`[profiles.gitops]` 예시:

```
[profiles.gitops]
sandbox_mode = "danger-full-access"
```

## 3. 현재 적용 상태

| 항목 | 값 |
|---|---|
| 기본 샌드박스 | `workspace-write` (상시) |
| 승인 정책 | `never` (사용자 설정 유지) |
| 예약 작업 | `CodexSandboxAclCleanup` 30분 간격, 상태 Ready |
| 마지막 청소 | 저장소 16곳, 찌꺼기 39건 제거 |
| 청소 후 잔여 | 0건 |

---

## 4. 운용 메모

- **비대화형 실행은 설정을 무시한다.** `codex exec`는 전체 접근으로 돌므로 `--sandbox workspace-write`를 직접 줘야 한다.
- **거부가 나면 순서대로 확인한다.** ① 점검 스크립트 실행 → ② `.git` 쓰기인지 확인(설계 동작) → ③ 작업 폴더 밖 경로인지 확인.
- **소유자가 바뀌는 증상**은 이 스크립트로 못 고친다. 관리자 권한에서 `takeown`으로 소유권을 되찾아야 한다.
- **예약 작업 해제**: `schtasks /Delete /TN CodexSandboxAclCleanup /F`
