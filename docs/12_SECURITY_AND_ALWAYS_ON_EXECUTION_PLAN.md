## 1. MIA Frame

### 목표

Codex PC 앱을 사용자 창구이자 총괄자로 두고, Claude Code CLI와 Antigravity CLI가 백그라운드에서 안전하게 대기·응답하도록 만든다. `.agent-swarm`은 작업·합의·감사 기록의 매개체가 된다.

### 성공 기준

1. 세 도구의 존재가 아니라 실제 요청-응답 가능 상태를 실측한다.
2. 위조된 에이전트·작업·표결을 브로커가 저장 전에 거부한다.
3. 원문 출력의 비밀정보가 Git 추적 기록으로 유입되지 않는다.
4. 인증·크레딧·할당량 장애가 재시도 폭주를 만들지 않는다.
5. 브로커 또는 워커 장애를 제한적으로 복구하고 복구 실패를 숨기지 않는다.
6. 정상 시 3/3 만장일치, 한 도구의 실측 불능 시에만 저위험 작업에 2/2 비상 정족수를 적용한다.

### 비목표

- Codex 앱 자체를 외부 프로세스가 임의로 깨우거나 자동 조작하는 기능
- 인증 토큰·쿠키·로그인 캐시의 수집 또는 공유
- 로컬 Ollama를 Claude Code나 Antigravity와 동등한 표결권자로 승격
- 검증 전 Windows 자동 시작 등록

## 2. /CRITIC — 현재 설계의 결함 순위

### BLOCKER

1. **브로커 세션 인증과 출처 증명이 없다.** 루프백 포트에 접근한 로컬 프로세스가 에이전트 등록, 작업 주입, 표결 위조를 시도할 수 있다. 현재 CLI가 제한 모드로 실행되므로 이를 곧바로 원격 코드 실행이라고 단정할 수는 없지만, 합의 신뢰성은 깨진다.
2. **원문 출력과 Git 추적용 기록이 분리되지 않았다.** 모델 출력에 토큰·경로·개인정보·프롬프트 주입 내용이 포함되면 `.agent-swarm` 기록과 Git을 통해 장기 보존될 수 있다.

### IMPORTANT

3. **사용량·인증 장애 회로 차단기(circuit breaker)가 없다.** 같은 실패를 반복하며 시간과 쿼터를 소모할 수 있다.
4. **감독자(supervisor)가 없다.** 브로커가 죽으면 워커만으로 복구할 수 없고, 단순 PID 재사용 검사는 다른 프로세스를 오인할 수 있다.
5. **생존과 응답 가능 상태를 혼동한다.** 하트비트는 스케줄러가 도는지만 보여준다. 자식 CLI의 응답성, 큐 지연, 진행 중 작업의 기한을 함께 보지 않으면 멈춘 작업을 정상으로 오판한다.
6. **원문 대화 재주입 경계가 약하다.** 다른 모델의 출력에 포함된 명령형 문장이 다음 에이전트의 지시로 승격될 수 있다.

### MINOR

7. **Windows 로그인 자동 시작이 없다.** 그러나 앞의 안전 장치보다 먼저 구현하면 결함도 자동 재시작하므로 마지막 단계로 미룬다.

### 자아비판과 과장 교정

- “프로세스가 살아 있다”를 “3자 실시간 합의가 가능하다”로 보고한 과거 표현은 과장이다.
- “루프백 무인증 = 즉시 RCE”라는 표현도 현재의 `plan/no-tools/stdin DEVNULL` 제약을 무시한 과장이다. 정확한 위험은 **출처 위조·합의 오염·쿼터 소진·기록 유출**이다.
- 정규식 가림만으로 모든 비밀정보 유출을 막을 수 있다고 주장해서는 안 된다. 원문 비추적, 구조화 필드, 출력 상한, 스캔을 겹쳐야 한다.

## 3. /REDTEAM — 공격·장애 시나리오

| 시나리오 | 재현 관점 | 합격 조건 |
|---|---|---|
| 위조 REGISTER | 인증 없는 클라이언트가 `claude`로 등록 | 저장·ROSTER 반영 전 거부되고 감사 이벤트만 남음 |
| 위조 TASK/표결 | 임의 로컬 프로세스가 작업 또는 YES를 전송 | HMAC/세션 검증 실패로 거부 |
| 원문 비밀정보 유출 | 출력에 가짜 API 키 패턴 삽입 | 원문은 Git 비추적, 추적 요약에는 비밀값 없음 |
| 쿼터 폭주 | `quota_exhausted`를 반복 반환 | 회로가 OPEN되고 냉각 전 호출 0회 |
| 작업 멈춤+하트비트 정상 | CLI 호출을 의도적으로 블로킹 | 작업 기한/큐 지연 경보가 하트비트 정상과 별도로 발생 |
| 브로커 강제 종료 | 처리 중 프로세스 종료 | 제한된 재시작, 작업 임대 만료, 중복 실행 방지 또는 명시적 실패 |
| PID 재사용 | 기존 PID가 다른 프로세스를 가리킴 | 프로세스 핸들/Job Object 식별로 오인 재시작·종료 없음 |
| 프롬프트 주입 릴레이 | 결과에 “다음 명령을 실행하라” 삽입 | 결과는 인용 데이터로 태그되며 제어 명령으로 해석되지 않음 |

## 4. /OPTIMIZE — 권장 구현 순서

다음 단계는 앞 단계가 검증된 뒤에만 시작한다. 각 단계 종료 시 3자 리뷰를 다시 요청한다. 한 도구가 실측 불능일 때만 `11_REALTIME_3P_AND_EMERGENCY_QUORUM.md`의 비상 정족수를 적용한다.

### Phase 0 — 동결·기준선·소유권 확인

**목적:** 보안 기능을 넣기 전에 현재 상태와 기존 변경의 소유자를 고정한다.

- 변경: 문서와 검사 결과만 갱신한다. 런타임 동작은 바꾸지 않는다.
- 검사:
  - `git status --short`, `git status --ignored` 전체 트리 감사
  - 현재 테스트 전체 실행과 실패 목록 고정
  - `.agent-swarm` 원문 파일의 비밀정보 패턴을 **값을 출력하지 않고** 개수·파일명만 검사
  - 브로커, 워커, ROSTER, 하트비트, 활성 작업 기한의 실측 스냅샷
- 합격: 기준선 보고서가 재현 가능하며 비밀값을 노출하지 않는다.
- 롤백: 문서 변경만 되돌리면 된다.
- 승인: 추가 승인 불필요. 읽기·검사와 프로젝트 내부 문서 갱신만 수행한다.

### Phase 1 — 로컬 전송 인증과 출처 증명

**목적:** 위조 등록·작업·표결을 저장 전에 차단한다.

- 대상: `csc_broker.py`, `csc_runtime.py`, `csc_agent_worker.py`, 관련 테스트
- 설계:
  - 활성화마다 회전하는 임시 세션 비밀을 `.agent-swarm/runtime/`에 둔다.
  - Windows ACL을 현재 사용자로 제한하고 Git에서 제외한다.
  - REGISTER와 모든 제어 프레임에 nonce, timestamp, HMAC을 적용한다.
  - 브로커 재시작 시 비밀을 회전하고 이전 프레임 재사용을 거부한다.
  - 인증 실패 데이터는 메시지 본문을 영속화하기 전에 버린다.
- 합격: 정상 3자 통신 통과, 무토큰·오토큰·재전송·만료 프레임 테스트 전부 통과.
- 롤백: 인증 기능 플래그를 끄고 기존 포그라운드 개발 모드로 복귀한다. 무인 상시 모드는 롤백 상태에서 금지한다.
- 승인: **필수.** 인증 상태와 ACL을 새로 만들기 전에 사용자 승인을 받는다.

#### 2026-09-04 딥리서치 정제

- 보안 경계는 세션 key가 노출되지 않은 협력적 단일 사용자 환경의 주입·변조·재전송 탐지다. 동일 사용자 계정의 완전한 침해를 막는다고 주장하지 않는다.
- 브로커 handshake만 인증하면 direct JSONL fallback과 worker RESULT 기록이 우회로가 된다. TASK·RESULT·BLOCKED·표결 envelope 자체를 서명하고 소비 시 검증한다.
- 인증 모드에서 의결 메시지의 unsigned fallback을 금지한다. 과거 unsigned 기록은 삭제하지 않고 `legacy_untrusted`로 분류한다.
- replay cache는 시간창 기반 TTL과 최대 크기를 가져야 한다.
- 로컬 transport의 장기 후보는 stdio 또는 Windows `AF_PIPE`지만, 현재 TCP를 한 번에 교체하지 않고 supervisor 단계에서 비교한다.
- Phase 1A 순수 인증 코어와 10개 테스트는 완료됐다. 상세 근거와 다음 단위는 `docs/15_PHASE1_SECURITY_RESEARCH/report-source.md`를 따른다.
- 실제 key 파일과 ACL 생성은 Phase 1D까지 미루며 그 직전에 사용자 승인을 다시 확인한다.

### Phase 2 — 원문/감사 기록 분리와 유출 방어

**목적:** 실시간 디버깅은 유지하되 Git에는 검토 가능한 정제 기록만 남긴다.

- 대상: `.gitignore`, 저장 계층, 요약 생성기, 커밋 전 검사
- 설계:
  - 원문 채널·모델 출력은 `.agent-swarm/runtime/raw/`에 로컬 비추적으로 저장한다.
  - Git 추적 영역에는 작업 ID, 판정, 근거 요약, 검증 결과만 저장한다.
  - 전체 버퍼에 대한 가림, 구조화 필드 허용 목록, 최대 출력 크기를 함께 적용한다.
  - 타 모델의 출력은 `UNTRUSTED_QUOTED_DATA`로 표시해 명령으로 승격되지 않게 한다.
- 합격: 가짜 키·쿠키·개인정보·긴 출력·분할 토큰 테스트에서 추적 파일 누출 0건.
- 롤백: 정제 요약 생성을 끌 수 있으나 원문 Git 비추적 원칙은 유지한다.
- 승인: **필수.** 이미 추적·스테이징된 원문 경로를 Git 인덱스에서 제외하는 변경은 사용자의 명시 승인을 받는다. 파일 자체는 삭제하지 않는다.

### Phase 3 — 공급자 회로 차단기

**목적:** 인증·크레딧·할당량 장애에서 재시도 폭주를 막고 정족수 판단에 실측 상태를 제공한다.

- 상태: `CLOSED → OPEN → HALF_OPEN → CLOSED`
- 분류: `quota_exhausted`, `auth_required`, `timeout`, `process_error`를 구분한다.
- 정책: 공급자가 제공한 재설정 시각을 우선하고, 없으면 지수 백오프와 최대 냉각 시간을 쓴다.
- 합격: OPEN 동안 모델 호출 0회, HALF_OPEN 단일 탐침, 성공 시 복구, 실패 시 재개방.
- 롤백: 회로 상태 파일을 안전하게 폐기하고 수동 포그라운드 호출로 복귀한다.
- 승인: 프로젝트 내부 코드·테스트는 승인 불필요. 실제 계정 로그인 변경은 별도 승인 대상이다.

### Phase 4 — 감독자와 실질 건강도

**목적:** 브로커·워커 장애를 탐지하고 제한적으로 복구한다.

- Windows 프로세스 핸들 또는 Job Object로 자식을 추적한다. bare PID만으로 종료·재시작하지 않는다.
- 건강도는 `ROSTER + heartbeat + queue age + active task deadline + last successful probe`로 계산한다.
- 재시작 횟수·시간 창·백오프 상한을 둔다. 한도를 넘으면 자동 복구를 멈추고 사용자에게 보고한다.
- 진행 중 작업은 임대(lease)와 멱등 키로 중복 실행을 통제한다.
- 합격: 브로커/각 워커 강제 종료, 작업 블로킹, 재시작 루프, PID 재사용 모의시험 통과.
- 롤백: 감독자를 종료하면 현재 수동 `activate` 방식으로 복귀한다.
- 승인: 프로젝트 내부 구현·고장 주입 테스트는 승인 불필요. 외부 프로세스 종료는 테스트 자식으로 한정한다.

### Phase 5 — 선택적 Windows 로그인 자동 시작

**목적:** 사용자가 로그인하면 브로커와 두 CLI 워커를 자동 활성화한다.

- 전제: Phase 1~4 전부 통과, 3자 리뷰 승인, 사용자 명시 승인.
- 방식: 사용자 범위 Task Scheduler 항목 하나와 제거 스크립트를 쌍으로 제공한다.
- 합격: 로그인 후 자동 기동, 로그아웃/재로그인, 네트워크 없음, 공급자 인증 만료, 제거 후 미기동 검증.
- 한계: 이 기능은 Codex 앱의 대화 턴을 외부에서 자동으로 깨우지 않는다. Codex 앱은 사용자와의 전면 창구이고, 브로커·CLI만 세션 수준 상시 대기한다.
- 롤백: 예약 작업 제거 후 수동 활성화로 복귀한다.
- 승인: **필수.** 운영체제 자동 시작 설정 변경이다.

### Phase 6 — 선택적 Ollama 비표결 보조자

**목적:** 외부 쿼터가 부족할 때 저비용 초안·분류·요약을 비동기로 지원한다.

- 현재 벤치마크: JSON·의미 검사는 통과했으나 응답 중앙값이 약 74초로 실시간 피어에 부적합하다.
- 역할: 비동기, 비표결, 기한 제한 보조자. Claude Code/Antigravity의 부재 표를 대신하지 않는다.
- 전제: 핵심 3자 안전 장치를 먼저 완성한다.

## 5. 단계 전환 게이트

각 단계는 다음 다섯 항목이 모두 충족돼야 `DONE`이다.

1. 해당 단계의 자동 테스트가 종료 코드 0으로 통과
2. 실제 런타임 스모크 테스트 통과
3. 새 비밀정보·개인정보·원문 출력이 추적 파일에 없음을 검사
4. Claude Code와 Antigravity의 비판 리뷰 및 Codex의 판정 기록
5. 승인 대상이면 사용자 승인 기록

실패하면 다음 단계로 넘어가지 않는다. 같은 원인으로 세 번 실패하면 재시도를 중단하고 원인, 보존 상태, 대안을 보고한다.

## 6. 첫 번째 실행 카드

다음 실제 작업은 **Phase 0** 하나만 수행한다.

- 입력: 현재 작업 트리, 테스트 명령, 실행 중 프로세스와 `.agent-swarm` 상태
- 출력: `docs/14_PHASE0_BASELINE_AND_SECURITY_AUDIT.md`
- 변경 허용: 위 보고서와 필요한 문서 인덱스 갱신만
- 금지: 토큰 생성, ACL 변경, Git 인덱스 변경, 자동 시작 등록, commit, push
- 완료 후: Phase 1 구현 전 사용자에게 인증 상태 생성 승인을 요청

## 7. 최종 합의 요약

세 도구는 현재의 상시 자동 시작을 승인하지 않았다. 의견이 일치한 핵심은 다음과 같다.

1. 인증과 기록 분리가 상시 실행보다 먼저다.
2. 하트비트 하나로는 실시간 응답성을 증명할 수 없다.
3. 쿼터 장애는 재시도하지 말고 회로를 열어야 한다.
4. 감독자는 bare PID가 아니라 운영체제 프로세스 정체성을 사용해야 한다.
5. Windows 자동 시작은 마지막의 선택 기능이다.

따라서 권장 순서는 **기준선 → 인증 → 기록 분리 → 회로 차단 → 감독자 → 자동 시작 → Ollama 보조**이다.
