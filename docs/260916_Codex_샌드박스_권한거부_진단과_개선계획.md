# Codex 샌드박스 권한 거부 — 진단과 개선 계획

- 작성: 2026-09-16
- 증상: 샌드박스를 켜고 작업하면 거부(denied)가 자주 발생함
- 환경: Windows 11, Codex CLI 0.154.0, `[windows] sandbox = "elevated"`

---

## 1. 결론

Codex의 Windows 샌드박스는 실행할 때마다 임시 계정을 만들고 저장소의 `.git` 폴더에 **거부(DENY) 권한**을 건다. 종료할 때 그 권한을 지우지 않아 실행할수록 쌓이고, 임시 계정이 삭제되면 이름이 풀리지 않는 **고아 SID**로 남는다. Windows에서는 거부가 허용보다 우선하므로, 그 뒤 샌드박스로 git을 쓰면 `.git/index.lock`이나 `FETCH_HEAD`를 만들지 못하고 거부된다.

이 저장소들에서 같은 흔적을 실제로 확인했고 제거했다.

---

## 2. 실측 증거 (정리 전)

| 대상 | `.git`의 거부 권한 | 저장소 루트의 고아 SID |
|---|---|---|
| `260823_codex-3p-orchestrator` | 4건 | 2개 |
| `260718_agentic-ai-platform-optimization` | 8건 | 4개 |

- 거부 대상 권한: 쓰기·삭제·권한변경(`W,D,Rc,DC`). git이 잠금 파일을 만들 때 필요한 권한과 정확히 겹친다.
- 권한 주체가 `S-1-5-21-…` 형태로만 표시된다. 계정이 이미 삭제됐다는 뜻이다.
- 두 저장소 모두 `CodexSandboxUsers` 그룹에 수정 권한이 부여돼 있다(현행 인프라이므로 유지).
- 소유자는 정상적으로 사용자 계정이었다. 소유자가 `CodexSandboxOffline`으로 바뀌는 더 심한 변종은 발생하지 않았다.

---

## 3. 원인 분석

1. **설계상 `.git` 보호.** 샌드박스가 git 이력을 지키려고 `.git`에 거부 권한을 걸지만, 종료 시 정리하지 않고 시작할 때마다 다시 건다. Codex 0.122 이후 보고됐고 공식 수정은 아직 없다.
2. **거부 우선 원칙.** `writable_roots`에 경로를 추가해도 소용없다. 거부가 허용을 이긴다.
3. **임시 계정 수명.** 샌드박스 계정이 만들어지고 사라지면서 SID만 남아 목록이 길어진다.
4. **승인 관련 버그.** 승인해도 여전히 샌드박스 안에서 실행되거나, `network_access = true`인데도 매번 승인을 요구하는 사례가 보고돼 있다.
5. **이름 해석 실패.** 계정이 삭제된 뒤에는 `icacls /remove`가 오류 1332(계정 이름과 SID를 연결할 수 없음)로 실패한다. SID를 직접 다뤄야 제거된다.

---

## 4. 조치한 것

- 두 저장소의 루트와 `.git`에서 상속되지 않은 고아 SID 항목 **19건**을 제거했다.
- 제거 후 거부 권한 0건, 고아 항목 0건, 두 저장소 모두 작업 트리 정상.
- 정리 전 권한 상태는 백업 폴더 `260915_C3P-restructure-backup/acl-before/`에 텍스트로 보존했다.

---

## 5. 재발 관리

샌드박스를 다시 켜면 거부 권한은 또 쌓인다. 공식 수정 전까지는 아래로 관리한다.

**점검**

```
pwsh -NoProfile -File tools\codex-sandbox-acl.ps1
```

고아 항목이 있으면 종료 코드 1로 알린다.

**정리**

```
pwsh -NoProfile -File tools\codex-sandbox-acl.ps1 -Mode Clean
```

**운용 규칙**

- 샌드박스를 켠 상태에서 git 명령이 거부되면, 먼저 위 점검을 돌린다. 권한 문제인지 다른 문제인지 한 번에 갈린다.
- 비대화형 실행은 설정을 무시하고 전체 접근으로 동작하므로 `--sandbox workspace-write`를 직접 준다.
- 소유자가 `CodexSandboxOffline`으로 바뀌는 증상이 나오면 이 스크립트로는 부족하다. 관리자 권한에서 소유권을 되찾아야 한다.

```
takeown /F "<저장소 경로>" /R /D Y
```
