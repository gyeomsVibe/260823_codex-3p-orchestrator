# Codex Windows 샌드박스 권한 거부 진단과 개선 계획

- 작성·재검토: 2026-09-16
- 환경: Windows 11 Enterprise LTSC, Codex CLI 0.154.0, 네이티브 Windows 샌드박스
- 증상: 일반 파일 편집은 되지만 `.git/index.lock`, `FETCH_HEAD` 같은 Git 메타데이터 쓰기가 거부됨

## 판정

Windows 11 Enterprise LTSC 자체가 근본 원인이라는 증거는 없다. 이 PC에서 샌드박스 전용 계정, 작업 폴더 쓰기, 홈·Windows 임시 폴더·네트워크 차단을 직접 확인했으므로 샌드박스의 핵심 경계는 작동했다.

확인된 실패는 두 층으로 나뉜다.

1. `workspace-write`가 `.git` 쓰기를 보호하는 제품 경계 때문에 샌드박스 안의 `git add`, `commit`, `fetch`가 실패한다. Windows의 명시적 `DENY` ACE는 허용 규칙보다 우선한다.
2. Windows가 이름을 표시하지 못하는 SID를 모두 고아 권한으로 간주하고 지운 기존 복구기가 정상 capability SID와 보호 ACE까지 삭제할 수 있었다. `%USERPROFILE%\.codex\cap_sid`에 등록된 SID도 Windows UI에서 `Account Unknown`처럼 보일 수 있다.

따라서 “ACL을 반복 삭제해 Git을 통과시킨다”는 방식은 샌드박스 정상화가 아니라 보호 경계를 일시적으로 제거하는 방식이다.

## 확인된 증거와 한계

| 증거 | 판정 | 한계 |
|---|---|---|
| 작업 폴더 쓰기 성공, 홈·`C:\Windows\Temp`·네트워크·`.git` 쓰기 실패 | 샌드박스 경계 작동 | 한 시점의 실측이며 모든 앱 버전을 대표하지 않음 |
| 예약 작업 직후 샌드박스 Git 쓰기 성공, 이후 DENY 재생성 후 실패 | ACL 삭제가 보호 경계를 제거했음 | 제품이 의도한 좁은 Git 승인 기능은 아직 없음 |
| `cap_sid` ledger와 ACL SID가 겹침 | 이름 미해석만으로 고아 판정 불가 | ledger 미등록 SID도 자동으로 고아가 되는 것은 아님 |
| GitHub #18918, #32880 | `.git` DENY와 Windows Git 실패가 공개 재현됨 | 사용자 보고이며 모든 세부가 공식 보장인 것은 아님 |
| GitHub #41169 | capability SID 오인 삭제 위험이 공개 보고됨 | 해당 보고의 SID 계열과 이 PC의 항목은 완전히 같지 않을 수 있음 |

## 즉시 수정

- `tools/codex-sandbox-acl.ps1 -Mode Clean`은 더 이상 ACL을 바꾸지 않고 종료 코드 3으로 거부한다.
- 유지관리 예약 작업은 ACL에 `-Mode Check`만 호출하고, Codex·Windows 버전 변경 시 경계 검사를 다시 실행한다.
- 점검기는 SID 후보를 `cap_sid` ledger 등록 여부와 함께 집계하되 삭제하지 않는다.
- 로그의 `stale`·`고아` 표현을 `sid_candidates`·`ledger_backed`·`unclassified`로 바꿨다. `unclassified`도 삭제 허가가 아니다.

## 영구 설정 적용

- 레거시 `sandbox_mode`와 `[sandbox_workspace_write]`를 사용자 설정에서 제거했다.
- `default_permissions = ":workspace"`로 공식 내장 프로필을 기본값으로 지정했다.
- `approval_policy = "on-request"`와 `approvals_reviewer = "auto_review"`를 조합해 경계 밖 작업을 자동 검토할 수 있게 했다.
- `git add/commit/fetch/pull/push`는 `sandbox-git-boundary.rules`에서 `prompt`로 분류했다.
- 샌드박스 Git이 사용자 전역 ignore 파일을 못 읽어 경고하던 문제는 ignore 파일의 로컬 사본과 Git 명령 전용 환경 설정으로 해결했다. 읽기 전용 예약 점검이 사본을 자동 복원한다. 비밀정보나 Git 인증 설정은 복사하지 않는다.
- `C:\tmp`는 이 Windows 구현에서 계속 차단되지만 실제 `%TEMP%`는 쓰기 가능하다. 일반 빌드·테스트 임시 파일은 `%TEMP%`를 사용한다.
- `CodexSandboxUpdateMaintenance` 작업은 로그온 시점과 30분마다 버전 지문을 비교한다. 바뀐 버전은 경계 검사 7개를 통과해야 마지막 정상 상태로 기록된다.

## 복구 순서

1. 오류가 작업 폴더 밖 쓰기, 네트워크, `.git` 쓰기인지 구분한다. 이 세 가지는 현재 경계에서 예상 가능한 거부다.
2. 일반 작업 파일이 거부될 때만 읽기 전용 점검을 실행한다.

   ```powershell
   pwsh -NoProfile -File tools\codex-sandbox-acl.ps1
   ```

3. SID 후보가 발견돼도 자동 삭제하지 않는다. `cap_sid` 등록 여부, 현재 실행 중인 Codex 세션, 대상 경로, 실제 실패를 함께 확인한다.
4. 소유권 또는 ACL 수리가 정말 필요하면 대상 하나와 복구용 SDDL 백업을 먼저 확정하고 사용자 승인을 받은 별도 작업으로 처리한다.

## 성공 기준

- 작업 폴더의 일반 파일 생성·수정·테스트가 성공한다.
- 홈, 시스템 임시 폴더, 승인하지 않은 네트워크 접근이 계속 차단된다.
- `.git` 실패를 일반 파일 쓰기 실패로 오진하지 않는다.
- 예약 작업 전후 ACL SDDL이 동일하다.
- 명시되지 않은 SID·ACE·계정·ledger 항목을 자동 삭제하지 않는다.
- Git 읽기 명령에 권한 경고가 없고, 보호된 Git 쓰기는 승인 경계로 전달된다.
