## 🌟 1. 10초 요약 (바쁘신 분을 위한 한눈에 보기)

인공지능 3총사(Codex, Claude Code, Antigravity)가 함께 일하는 **C3P 협의체(C3P Council, 세 도구가 함께 회의하고 일하는 운영 모임)**에서 오늘 두 가지 큰 문제를 완벽하게 해결하고 깃허브에 모두 저장했습니다:

1. **"가장 돈을 많이 아껴주는 비법이 왜 소개글에 없지?"**
   - ➡️ 외부 유료 인공지능 비용을 **80% 이상 아껴주는 '예산절약 모드'**를 저장소 소개글([`README.md`](../README.md)) 전면에 그림과 실측 표로 알기 쉽게 등록했습니다.
2. **"윈도우 컴퓨터에서 일꾼들이 가끔 갑자기 뻗거나 멍때리는 문제"**
   - ➡️ 윈도우가 파일을 잠깐 잠갔다고 일꾼이 혼자 기절(종료)해버리던 버그를 고치고, 겉으로는 살아있는데 통신이 끊긴 좀비 일꾼을 스스로 감지해 다시 깨워주는 **안전 보호장치**를 완성했습니다. (총 **272개 단위 테스트 100% 합격** 완료)

## 🧭 2. 기획 (Frame) — 무슨 일이 일어났었나요?

### 문제 1: 정작 가장 중요한 '돈 아끼는 기술'이 리드미에서 빠져 있었습니다
- 우리 프로젝트 내부에는 **비대칭 쿼터(asymmetric quota, 인공지능 도구마다 서로 다르게 남아 있는 사용량 한도)**를 활용하여, 배터리가 3%밖에 남지 않은 사령관 Codex를 쉬게 하고 무제한으로 쓸 수 있는 Antigravity가 대신 말을 전하는 똑똑한 절약 기술이 이미 완성되어 있었습니다.
- 하지만 깃허브 메인 소개글(`README.md`)에는 "우리는 한 몸처럼 일해요"라는 비유만 적혀 있고, **실제로 어떻게 토큰(돈)을 아끼는지**가 적혀 있지 않아 사용자가 날카롭게 지적해 주셨습니다.

### 문제 2: 전체 점검을 돌렸더니 숨어 있던 윈도우 결함 2개가 발견되었습니다
- 시스템 전체를 전수 검사(`MIA c3p 발동`)했더니, 평소엔 숨어 있다가 윈도우 환경에서만 터지는 골칫거리 두 개가 발견되었습니다:
  1. **워커 돌연사 버그**: 윈도우가 파일 문을 1초 동안 잠깐 잠갔을 뿐인데, 일꾼이 "문이 안 열린다!"면서 스스로 목숨을 끊어버리는(프로세스 종료) 문제.
  2. **유령(좀비) 일꾼 방치 버그**: 일꾼의 통신선(소켓)이 끊겨서 일을 못하는데도, 심장박동 기록 파일은 계속 찍히고 있어서 시스템이 "어? 쟤 정상인데?" 하고 착각하여 새로 깨우지 못하던 문제.

## 🛠️ 4. 실행 (Execute /ELI10 & /OPTIMIZE) — 어떻게 마법처럼 고쳤나요?

### 해결책 1: 깃허브 소개글(README.md)에 예산절약 모드 공식 등재
* 사령관 Codex의 남은 3% 힘을 아껴두고, Antigravity가 **상임 대변인(spokesperson, 사령관을 대신하여 사용자에게 길고 자세한 내용을 전문적으로 브리핑해 주는 공식 발표자)**이 되어 길고 자세한 보고를 전담합니다.
* 내 컴퓨터 안의 작은 인공지능인 **소형언어모델(SLM: Small Language Model, 컴퓨터 자원을 적게 쓰면서 로컬에서 빠르게 실행되는 작은 인공지능 모델)**을 사용하여, 텍스트 정리나 정규식 추출 같은 단순 노동을 **0원 오프로딩(offloading, 무거운 작업의 일부를 덜어서 다른 가벼운 도구에 맡겨 처리하는 기술)**으로 해결합니다.
* 여러 도구가 동시에 파일을 건드려 충돌하지 않도록 **펜싱 토큰(fencing token, 여러 작업자가 동시에 같은 파일에 접근하지 못하도록 순번을 매겨 통제하는 고유 번호표)**을 나눠주어 질서를 지킵니다.

### 해결책 2: 윈도우 파일 잠금에 10번 노크하는 지수 백오프 적용
* 문이 잠겨 있어도 바로 포기하지 않고, 시간을 조금씩 늘려가며 최대 10번 다시 노크하는 **지수 백오프(exponential backoff, 실패할 때마다 기다리는 시간을 2배씩 늘려가며 충돌을 피하는 방법)** 기술을 넣었습니다.
* 파일 쓰기가 1~4번 실패해도 데몬이 바로 죽지 않고 참아주는 **서킷 브레이커(circuit breaker, 일시적 오류가 발생했을 때 전체 시스템이 망가지지 않도록 안전하게 차단하고 복구를 기다려 주는 안전장치)**를 달아 돌연사를 100% 차단했습니다.

### 해결책 3: 심장박동과 무전기를 둘 다 확인하는 이중 감시자 도입
* 이제 관리자는 일꾼의 심장박동 타임스탬프(**라이브니스 프로브(liveness probe, 프로그램이 죽지 않고 살아 숨 쉬고 있는지 확인하는 생명 검사)**)뿐만 아니라, 실제 무전기가 연결되어 있는지(**레디니스 프로브(readiness probe, 프로그램이 실제로 손님을 받을 준비가 되었는지 네트워크 연결 상태를 확인하는 준비 검사)**)까지 동시에 확인합니다.
* 무전기가 끊긴 좀비 일꾼을 발견하면, 관리자가 즉시 깨워서 다시 연결해 주는 **자가 치유(self-healing, 사람이 손대지 않아도 프로그램이 스스로 문제를 고치고 회복하는 능력)**를 완성했습니다.

1. **272개 단위 테스트 전수 합격**:
   - 새로 추가한 윈도우 동시성 테스트 3건을 포함하여, 프로젝트 내 **272개 시험을 단 10초 만에 100% 통과**했습니다.
2. **원격 깃허브 저장소 일치율 100%**:
   - 모든 수정 파일이 깃허브 원격 저장소(`main` 브랜치)에 안전하게 푸시되었으며, 컴퓨터의 최신 상태(`HEAD`)와 깃허브의 상태(`origin/main`)가 **`33d485b`라는 고유 암호값으로 완벽히 일치**함을 확인했습니다.
