# C3P 협의체 공식 명칭과 바로 쓰는 방법

## 한 문장 정의

**C3P 협의체(C3P Council, Codex·Claude Code·Antigravity가 함께 검토하고 실행하는 3도구 협업 체계)**는 `codex-3p-orchestrator` 프로젝트 안에서 세 AI 도구가 역할을 나누고 결과를 합의하는 운영 체계의 공식 속칭이다.

## 무엇을 어떻게 부르는가

| 구분 | 공식 표기 | 쉬운 뜻 |
|---|---|---|
| 프로젝트·Git 저장소 | `codex-3p-orchestrator` | 협업 코드와 규칙을 보관하는 장소 |
| 세 도구 운영 협의체 | `C3P 협의체` | Codex·Claude Code·Antigravity가 함께 일하는 팀 |
| 통신 기반 | CSC 로컬 제어면(control plane, 세 도구가 작업과 결과를 주고받는 통로) | `.agent-swarm`과 `csc.py`로 이루어진 우편실 |
| 실제 가동 | C3P 활성 상태(active state, 세 작업자가 연결되고 최근 신호를 보내는 상태) | 지금 세 도구가 실제로 연락 가능한 상태 |

협의체 구성원은 Codex·Claude Code·Antigravity 세 AI 도구다. 사용자는 지시하고 승인하는 주체이며, CSC 브로커는 메시지를 나르는 통신 기반이므로 둘 다 표결 구성원으로 세지 않는다. `단일 지능 유기체`는 세 도구의 역할 결합 구조를 설명하는 비유이고, `C3P 협의체`는 검토·합의를 수행하는 운영 주체의 이름이다.

`C3P`는 이 프로젝트에서 사용하는 브랜드·호출 식별자다. 확인된 정본이 없는 영문 확장어를 임의로 만들어 설명하지 않는다.

## 바로 쓰는 호출 예

- `c3p 발동` — 대소문자와 관계없이 C3P 실기동 절차를 시작한다.
- `MIA 씨3피 발동` — MIA 전략 절차와 C3P 협업을 함께 요청한다.
- `C3P 협의체와 검토해줘` — 세 도구의 실제 회신과 합의를 요구한다.

## 상태를 혼동하지 않는 법

폴더가 있다고 팀이 출근한 것은 아니다. 다음 세 단계는 따로 확인한다.

1. **프로젝트 존재:** 정본 경로와 Git 저장소를 확인한다.
2. **세 도구 연결:** `python csc.py roster`와 작업자 하트비트(heartbeat, 살아 있음을 주기적으로 알리는 신호)를 확인한다.
3. **세 도구 합의:** 같은 작업 식별자에 대한 Claude Code와 Antigravity의 `RESULT` 원문, Codex의 최종 판정을 확인한다.

응답 제한 시간이 끝나 `PENDING`(처리 중)이라면 실패나 반대로 바꾸지 않는다. `resubmit: false`이면 같은 작업을 다시 보내지 않고 늦게 도착한 결과를 이어서 확인한다.

## 사용자에게 보고하는 고정 형식

1. **무엇이:** 연결, 응답, 합의 가운데 확인된 상태를 적는다.
2. **왜:** `roster`, 하트비트, `RESULT`처럼 판단에 쓴 근거를 적는다.
3. **사용자가 할 일:** 없으면 `지금 할 일 없음`, 승인이 필요하면 승인 대상을 한 문장으로 적는다.

## 적용 범위

C3P 실행 절차는 이 프로젝트 안이거나 사용자가 설치된 `codex-3p-orchestrator` 스킬을 명시적으로 호출했을 때 적용한다. 다른 프로젝트가 이 이름을 언급했다는 이유만으로 세 도구가 연결되거나 합의했다고 간주하지 않는다.
