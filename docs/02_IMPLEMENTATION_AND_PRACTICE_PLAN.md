# 3대 도구 통합 구현·실습 계획

작성일: 2026-08-23 KST

## 목표 결과물

1. `.agent-swarm` 기반 협업 제어면과 실제 장기 세션 2개
2. 단일 HTML `오늘 뭐 먹지?` 앱과 자동 기능 검증
3. Codex·Claude Code·Antigravity 역할별 비교 기록
4. 승인 시 GitHub 저장과 Render 공개 URL
5. 승인 시 Ollama `qwen3.5:0.8b`의 한국어 응답 증거
6. 반복 사용 가능한 Codex 스킬 초안의 요구사항과 검증 데이터

## 단계별 절차

### Step 0 — 기준선과 통신 제어면

- `docs` 정본 인덱스, MIA 결정문, 실행계획을 만든다.
- `.agent-swarm` 역할·통신·승인 규약을 만든다.
- Local Agent Runtime과 Antigravity bridge 상태를 확인한다.
- Claude Code·Antigravity 장기 세션을 하나씩 연다.

수용 기준: 두 세션 ID, 기본 안전값, 역할 카드가 기록된다.

### Step 1 — 읽기 전용 3분할 실험

- Codex: 교안 원문과 전체 목표를 통합한다.
- Claude Code: 프로토콜·아키텍처·테스트 누락을 검토한다.
- Antigravity: 초보자 UX·도구 비교·가시적 결과물을 검토한다.
- Codex가 상충 의견을 중계하고 최종 실험 설계를 문서화한다.

수용 기준: 각 도구의 고유 기여, 중복, 충돌, 소요시간을 기록한다.

### Step 2 — 최소 가시적 구현

- 기본 산출물은 별도 서버 없는 단일 HTML 앱이다.
- 필수 기능은 무작위 메뉴, 한식·중식·일식·양식·간식, 큰 이모지, 재추천, 최근 3개 기록이다.
- 모바일 버튼 크기, 기존 파일 보호, 반복 클릭 검증을 포함한다.
- 구현 소유자는 한 명만 두고 다른 둘은 읽기 전용 리뷰를 한다.

수용 기준: 브라우저에서 기능을 직접 실행하고 최근 3개가 정확히 유지된다.

### Step 3 — 도구 비교 계측

- 계획 품질, 범위 준수, 결과 가시성, 수정 정확도, 오류 복구, 사용자 개입 횟수를 기록한다.
- 동일한 성공 기준으로 평가하되 도구별 역할 차이를 별도 표기한다.

수용 기준: “최고의 도구”가 아니라 작업 유형별 최적 역할을 설명할 수 있다.

### Step 4 — GitHub·Render 확장

- 사용자에게 저장소 공개 범위와 URL을 확인한다.
- 민감정보·불필요 파일을 전체 감사한다.
- 현재 폴더의 Git 초기화는 사용자 승인 후 Codex가 수행한다.
- 로컬 실행 검증 후 필요한 파일만 커밋한다.
- push와 Render 배포는 실행 직전 별도 승인받는다.

수용 기준: GitHub 파일 확인, Render URL에서 앱 로드, 로컬과 배포 기능 일치.

### Step 5 — 로컬 AI 실험

- Ollama 설치 여부, 버전, 모델 존재, 저장 공간을 읽기 전용으로 확인한다.
- 설치나 모델 다운로드가 필요하면 목적·용량·영향·롤백을 설명하고 승인받는다.
- 모델 실행 후 “안녕하세요”에 의미 있는 한국어 응답이 나오는지 검증한다.

수용 기준: 설치 버전, 정확한 모델명, 응답 성공 여부, 실패 시 원인이 기록된다.

### Step 6 — 스킬화

- 실험 로그에서 안정적인 메시지 봉투, 역할 라우팅, 승인 게이트, 실패 패턴을 추출한다.
- Codex 스킬의 입력·출력·도구 선택·안전 규칙·검증 스크립트 요구사항을 작성한다.
- 세션 복구, 경로 이동, 동시 호출, 타임아웃을 테스트한다.

수용 기준: 다른 프로젝트에서 재현 가능한 최소 스킬 명세와 테스트 시나리오가 완성된다.
